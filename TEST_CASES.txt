Предусловие: задача 30.07.2026 15:00, интервал 60 минут.
В 30.07.2026 14:00 OUTPUT WA:
Задача: <название>, срок 30.07.2026 15:00
RESULT: reminder.status=sent, sent_at заполнено.

TC-DEL-002. Напоминание в момент задачи
Предусловие: задача 30.07.2026 15:00.
В 30.07.2026 15:00 OUTPUT WA:
Задача: <название>, срок 30.07.2026 15:00
RESULT: отправляется ровно одно due-time уведомление.

TC-DEL-003. Защита от повторной отправки
INPUT: планировщик несколько раз выбирает один момент напоминания.
RESULT: уникальная комбинация task_id + minutes_before + occurrence_at;
        успешное напоминание отправляется один раз.

TC-DEL-004. Перенос задачи
Предусловие: задача перенесена с 15:00 на 17:00.
RESULT: уведомления для 15:00 отменены; отправляются только уведомления,
        рассчитанные от 17:00.

TC-DEL-005. Завершенная задача
Предусловие: задача завершена до срока.
RESULT: ожидающие напоминания отменены и не отправляются.

TC-DEL-006. Удаленная задача
Предусловие: задача удалена до срока.
RESULT: напоминания не отправляются.

TC-DEL-007. Ошибка Meta API
INPUT: Meta временно отвечает 500/timeout.
RESULT: attempts увеличивается; ошибка записывается; после максимального числа
        неудач reminder.status=failed; успешная доставка не помечается заранее.

TC-DEL-008. Напоминание вне 24-часового окна
RESULT: используется разрешенный шаблон Meta, настроенный для напоминаний.

TC-DEL-009. Работоспособность очереди
ПРОВЕРКА:
docker compose ps
EXPECTED: api, worker, beat, db и redis имеют статус Up; db/redis healthy.

11. ПОВТОРЯЮЩИЕСЯ ЗАДАЧИ

TC-REC-001. Ежедневная задача
INPUT WA: Добавь принимать лекарство каждый день в 09:00
EXPECTED: recurrence.frequency=daily; после наступления срока создается
          следующая дата на следующий день; напоминания пересоздаются.

TC-REC-002. По будням
INPUT WA: Добавь стендап по будням в 10:00
EXPECTED: recurrence.frequency=weekdays; после пятницы следующая дата —
          понедельник.

TC-REC-003. Еженедельная
INPUT WA: Добавь отчет каждую пятницу в 17:00
EXPECTED: recurrence.frequency=weekly.

TC-REC-004. Ежемесячная
INPUT WA: Добавь оплатить аренду каждый месяц 1 числа в 09:00
EXPECTED: recurrence.frequency=monthly.

TC-REC-005. Пользовательский интервал
INPUT WA: Добавь проверку каждые 3 дня в 12:00
EXPECTED: recurrence.frequency=interval, interval=3.

TC-REC-006. Пропущенные повторения
Предусловие: сервис был выключен несколько периодов.
RESULT: задача переносится на ближайшее будущее повторение, а не остается
        бесконечно просроченной.

ПРИМЕЧАНИЕ: кейсы TC-REC-001—005 должны считаться приемочными только после
подтверждения, что текущий natural-language parser распознает соответствующие
формулировки без LLM. При недоступной LLM бот не должен создавать неправильное
правило повторения.

14. КРИТЕРИИ ОБЩЕЙ ПРИЕМКИ
===============================================================================

Система считается прошедшей основную приемку, если одновременно выполнено:

1. Новый WhatsApp-пользователь проходит регистрацию.
2. Пользователь создает задачу естественной фразой.
3. При отсутствии даты, времени или интервала бот задает уточняющий вопрос.
4. Бот отправляет предварительные и due-time напоминания без дублей.
5. Перенос отменяет старые предупреждения.
6. Сводки не дублируют задачи и соблюдают приоритеты.
7. Задача без срока попадает только в соответствующий раздел.
8. Текстовое приглашение и ICS от подтвержденной почты требуют подтверждения.
9. Неизвестный email не создает задачу.
10. Смена часового пояса не меняет сроки и отображение старых задач.
11. Новые задачи используют новый часовой пояс.
12. Замена email происходит только после правильного OTP.
13. Повторная доставка webhook или письма не создает дубликат.
14. API, worker, beat, PostgreSQL и Redis остаются работоспособными.
